# Deployment Guide — AI Maintenance Safety & Quality Monitor

Three pieces need hosting:

| Piece | Provider | What it runs |
| --- | --- | --- |
| Frontend (SPA) | **Vercel** | Vite + React app (this repo root) |
| Backend (FastAPI) | **Render** | Python API + WebSockets (in `ai-maintenance-backend/`) |
| Database | **Render PostgreSQL** | managed Postgres, provisioned by the blueprint |
| App data layer | **Convex** | production deployment of the `src/convex/` functions |

The FastAPI backend is the "AI backend" — the frontend calls it for login, PPE
checks, camera-frame detection, SOP verification, alerts and scoring. Convex
holds the jobs/workers/SOP data the dashboards render.

---

## 1. Convex production deployment (do first)

The frontend needs a Convex URL that the production build can talk to.

```bash
bun convex deploy
```

This creates/promotes a production deployment. Copy the production URL
(e.g. `https://<slug>.convex.cloud`) — you'll set it as `VITE_CONVEX_URL` on
Vercel. The demo data seeder (`useEnsureDemoData`) runs automatically on the
frontend, so no manual seeding is needed.

## 2. Backend on Render (FastAPI + PostgreSQL)

The repo already contains `ai-maintenance-backend/render.yaml` (blueprint).

1. Go to https://render.com and create a free account (GitHub sign-in is fastest).
2. Dashboard → **New +** → **Blueprint**.
3. Connect the `jenisia-tech/AI-monitor` repo. Render reads `render.yaml`,
   creates a **free PostgreSQL database** and a **free Python web service**,
   and wires `DATABASE_URL` automatically.
4. After the first deploy, open the service → **Environment** and confirm:
   - `JWT_SECRET` — auto-generated by the blueprint (fine as-is)
   - `CORS_ORIGINS` — must include your **Vercel frontend URL**
     (e.g. `["https://ai-monitor-<you>.vercel.app"]`) plus `http://localhost:5173`
   - `AI_MODE=demo` (simulated, honest) — switch to `production` later when you
     add real YOLO weights
   - `SEED_DEMO_DATA=true` — seeds `worker@demo.com / worker123` etc. on boot
5. Click **Manual Deploy → Deploy latest commit**.
6. Verify: open `https://<your-service>.onrender.com/health` → should return
   `{"success": true, ...}`.

> Free tier note: Render free web services spin down after 15 min idle and take
> ~30 s to wake; free Postgres expires after 30 days. Fine for a demo — upgrade
> the plan when you go live.

## 3. Frontend on Vercel

1. Go to https://vercel.com and sign in with GitHub.
2. **Add New → Project** → import `jenisia-tech/AI-monitor`.
3. Vercel auto-detects Vite from `vercel.json` (build `bun run build`,
   output `dist`, SPA rewrites already configured).
4. In **Settings → Environment Variables** (Production) set:

   | Variable | Value |
   | --- | --- |
   | `VITE_CONVEX_URL` | your Convex production URL from step 1 |
   | `VITE_AI_API_URL` | your Render backend URL, e.g. `https://amsq-backend.onrender.com` |

5. **Deploy**. The preview URL (e.g. `https://ai-monitor-<you>.vercel.app`)
   is your live app.
6. Back on Render, add that exact URL to `CORS_ORIGINS` and redeploy.

## 4. Smoke test

- Open the Vercel URL → sign in as **supervisor@demo.com / super123**
  (backend JWT login; the FastAPI service must be awake).
- Worker flow: sign in as **worker@demo.com / worker123** → PPE check →
  journey → worksite → **Maintenance Monitor**. With `VITE_AI_API_URL` set the
  AI badge reads **PRODUCTION**; the camera feed analysis hits the real backend.
- Open `https://<your-service>.onrender.com/docs` for the Swagger UI.

## Env var reference (backend, `ai-maintenance-backend/env.example`)

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | PostgreSQL connection string (blueprint sets it) |
| `JWT_SECRET` | long random string ≥32 bytes (blueprint generates) |
| `AI_MODE` | `demo` (default) or `production` (real YOLO weights) |
| `SEED_DEMO_DATA` | seed demo dataset on startup (default `true`) |
| `CORS_ORIGINS` | JSON array of allowed frontend origins |
| `S3_*` | optional S3-compatible object storage for frames/videos |
| `MAX_UPLOAD_MB` | upload size cap (default 10) |
